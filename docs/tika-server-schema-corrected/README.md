## UD30 fix applied in this conversion

`UD30.csv` is `UD.csv` filtered at a 30% instability threshold: a severity view of the same
unstable dependencies, not a second set of findings. The previous converter emitted one row per
file and therefore counted every severe pair twice.

The effect on the Tika set regenerated alongside this one:

| | before | after |
|---|---|---|
| `smell-characteristics.csv` | 260 | **252** |
| of which unstableDep | 86 | **78** |
| `smell-affects.csv` | 596 | **588** |
| `component-metrics.csv` | 2,051 | 2,051 (unaffected) |

Nothing is lost: a pair that also appears in `UD30.csv` now carries
`[severe: instability >= 0.30]` in its `Detail` column instead of occupying a second row. On
commons-validator 2 of the 4 unstable pairs are flagged this way.

Verified across 64 Arcan runs: `UD30` is a subset of `UD` in every one, with no pair unique to
`UD30`. The converter still reads both files and deduplicates by pair, so a pair appearing only
in the 30% view would be emitted once rather than dropped.
